## :dart: O guia para alavancar a sua carreira

> Materialize CSS nasceu em 2014, criado por um grupo de estudantes logo depois de o Google lançar as diretrizes de Material Design — e por alguns anos foi uma das formas mais rápidas de dar a "cara" do Android/Google a um site, com grid, componentes prontos e ícones do Material Design fora da caixa. O repositório original, o `Dogfalo/materialize`, parou praticamente no lugar depois da versão 1.0.0 (2018) e ainda depende de jQuery. Quem manteve o framework vivo foi a comunidade: o fork `materializecss/materialize` reescreveu tudo em TypeScript/JavaScript puro (sem jQuery) e segue lançando versões novas — a atual é a 2.3.3. Este guia reúne a documentação dos dois lados (o legado e o fork ativo), o pouco de conteúdo em português que ainda existe sobre o tema, ferramentas do ecossistema e as comunidades gerais de front-end que ajudam quem estiver com Materialize em mãos hoje. Todo link foi verificado. Use-o como apoio para os seus estudos, no seu ritmo.

## 🗺️ Roadmap

- [roadmap.sh — Frontend Roadmap](https://roadmap.sh/frontend) — O caminho completo de front-end em que um framework CSS como o Materialize se encaixa, ao lado de HTML, CSS e JavaScript.
- [Releases do materializecss/materialize](https://github.com/materializecss/materialize/releases) — Histórico de versões do fork mantido pela comunidade; a mais recente é a 2.3.3.
- [Milestones do materializecss/materialize](https://github.com/materializecss/materialize/milestones) — O que a equipe do fork ativo está planejando para as próximas versões.
- [Releases do Dogfalo/materialize](https://github.com/Dogfalo/materialize/releases) — Histórico de versões do projeto original, que estacionou na 1.0.0 (2018).

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **HTML, CSS e JavaScript básicos** — o Materialize é uma camada de classes CSS e componentes JS sobre a base da web; domine seletores, box model e Flexbox antes de começar.
2. **Escolha a versão** — o `Dogfalo/materialize` (v1, 2018, depende de jQuery) ainda aparece em projetos legados e tutoriais antigos; para projetos novos, use o fork ativo `materializecss/materialize` (v2, TypeScript, sem jQuery).
3. **Instalação** — via CDN (mais rápido) ou `npm install @materializecss/materialize` (compilando com Sass, para customizar cores e variáveis).
4. **Grid de 12 colunas** — o sistema de layout baseado em Flexbox, com classes como `row`, `col`, `s12 m6 l4` para os breakpoints small/medium/large.
5. **Componentes prontos** — Cards, Modals, Navbar, Sidenav, Collapsible, Tabs, Carousel e Parallax, todos seguindo a linguagem visual do Material Design.
6. **Formulários e Material Icons** — classes de formulário próprias (`input-field`) e a fonte de ícones do Google integrada por padrão.
7. **Inicialização dos componentes JS** — no fork v2, componentes interativos (Modal, Sidenav, Tooltip etc.) são inicializados via `M.ComponentName.init(elems)`, em JavaScript puro; na v1 legada, a inicialização é via jQuery (`$('.modal').modal()`).
8. **Customização com Sass** — variáveis (`$primary-color`, `$secondary-color`) e partials Sass para recompilar o Materialize com sua própria identidade visual.

**Por onde começar:**

1. **Leia a introdução oficial** em [Getting Started](https://materializeweb.com/getting-started.html) — o que o framework resolve e como instalar.
2. **Explore a paleta de cores** em [Color](https://materializeweb.com/color.html) — o Materialize embute toda a paleta de cores do Material Design como classes utilitárias prontas.
3. **Aprenda o grid na prática** com [Grid](https://materializeweb.com/grid.html), testando `row`/`col s12 m6` no navegador.
4. **Monte sua primeira página** combinando [Navbar](https://materializeweb.com/navbar.html), [Cards](https://materializeweb.com/cards.html) e [Buttons](https://materializeweb.com/buttons.html).
5. **Adicione um componente interativo**, como [Modals](https://materializeweb.com/modals.html) ou [Sidenav](https://materializeweb.com/sidenav.html), e confirme a inicialização em JavaScript puro (`M.Modal.init(...)`).
6. **Veja o código-fonte** do [materializecss/materialize](https://github.com/materializecss/materialize) para entender como os componentes são organizados internamente.
7. **Pratique em vídeo** com os canais generalistas de CSS/front-end listados na seção de YouTube abaixo — não há canal dedicado ao Materialize hoje, então use-os para reforçar Sass e Flexbox.
8. **Publique no GitHub** — seu primeiro item de portfólio com Materialize de verdade, linkado no currículo.

Sua primeira página em 30 segundos (via CDN, fork ativo `@materializecss/materialize` v2.3.3):

```html
<!-- index.html -->
<!doctype html>
<html lang="pt-br">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <link rel="stylesheet" href="https://fonts.googleapis.com/icon?family=Material+Icons" />
    <link
      rel="stylesheet"
      href="https://cdn.jsdelivr.net/npm/@materializecss/materialize@2.3.3/dist/css/materialize.min.css"
      integrity="sha384-LsoO5h1gRpqwGOHXBKeshxbf0jxlJ0FI9VBL6+/I0dXqWJcoKd6BhMAiWRVBNHG9"
      crossorigin="anonymous"
    />
  </head>
  <body>
    <div class="container">
      <div class="row" style="margin-top: 40px;">
        <div class="col s12 m6">
          <div class="card">
            <div class="card-content">
              <span class="card-title">Olá, Guia Dev Brasil!</span>
              <p>Sua primeira página com Materialize CSS.</p>
            </div>
            <div class="card-action">
              <a href="#">Comece aqui</a>
            </div>
          </div>
        </div>
      </div>
    </div>

    <!-- fork ativo: JavaScript puro, sem dependência de jQuery -->
    <script
      src="https://cdn.jsdelivr.net/npm/@materializecss/materialize@2.3.3/dist/js/materialize.min.js"
      integrity="sha384-anRYl3T8dVyoXaqhjg3UFtZ3HgPeL/LrNzBalHuDXA26K/wTEYNz/zrDPgGQrlGP"
      crossorigin="anonymous"
    ></script>
  </body>
</html>
```

Abra o `index.html` no navegador — o card já aparece estilizado com o grid `row`/`col`, e o script inicializa automaticamente os componentes que usam `data-*` (para os que exigem inicialização manual, como Modal ou Sidenav, chame `M.ComponentName.init(elems)` depois do carregamento).

## 🤖 IA na prática

Materialize CSS é um caso particular para IA generativa por causa da divisão entre versões: o `Dogfalo/materialize` original (v1, 2018) depende de **jQuery** e inicializa componentes como `$('.modal').modal()`, enquanto o fork ativo `materializecss/materialize` (v2) foi reescrito em **JavaScript/TypeScript puro**, sem jQuery, e inicializa os mesmos componentes como `M.Modal.init(elems)`. Como a maior parte do conteúdo público sobre Materialize na internet (tutoriais, Stack Overflow, repositórios antigos) é da era jQuery, os modelos de IA tendem a **misturar as duas sintaxes** ou sugerir a API antiga mesmo quando você está usando o fork moderno. Outro risco recorrente: a IA **"resvalar" para Bootstrap ou Tailwind** sem avisar, porque viu muito mais desses dois frameworks em treinamento do que Materialize.

**Para aprender**
- Peça para **explicar um componente com um exemplo executável** em ambas as sintaxes — a inicialização via jQuery (`$('.sidenav').sidenav()`, v1) e via JavaScript puro (`M.Sidenav.init(elems)`, v2) — e cole o resultado em um [StackBlitz](https://stackblitz.com/) ou [JSFiddle](https://jsfiddle.net/) para ver qual realmente funciona com o pacote que você instalou.
- Cole um trecho de JavaScript e pergunte: *"essa inicialização é do Materialize v1 (jQuery) ou do fork v2 (JS puro)?"* — depois confirme na [documentação oficial](https://materializeweb.com/getting-started.html) do fork ativo.
- Peça **exercícios com gabarito** sobre o tópico que está estudando (grid, formulários, componentes) e resolva antes de olhar a resposta.
- Sempre que a IA sugerir uma classe ou método (`M.ComponentName.init`, `data-target`), confirme na página do componente correspondente na [documentação oficial](https://materializeweb.com/getting-started.html).

**Para trabalhar**
- Use [GitHub Copilot](https://docs.github.com/pt/copilot), [Cursor](https://cursor.com/), [Claude Code](https://code.claude.com/docs/en/overview) ou [Gemini CLI](https://github.com/google-gemini/gemini-cli) para gerar a marcação HTML de componentes do Materialize, mas **diga explicitamente "usando o Materialize CSS 2 (fork materializecss, sem jQuery)"** no prompt — sem isso, é comum a IA responder com a sintaxe jQuery antiga ou até migrar sozinha para Bootstrap.
- Ferramentas de **design para código** como [v0 (Vercel)](https://v0.app/), [Builder.io](https://www.builder.io/) e [21st.dev](https://21st.dev/) geram interfaces a partir de um prompt — o resultado quase sempre vem em Tailwind ou React puro; adaptar para classes do Materialize (grid `row`/`col`, `card`, `input-field`) exige revisão manual, não apenas um "converta para Materialize" no prompt.
- Depois de **cada** sugestão aceita, confira no navegador se os componentes interativos (Modal, Sidenav, Tooltip, Select) foram de fato inicializados — no fork v2 isso exige uma chamada explícita a `M.ComponentName.init(...)` depois do carregamento da página, e a IA às vezes esquece essa linha.
- Se o projeto que você está mantendo ainda usa a v1 (jQuery), avise a IA disso em toda sessão nova — ela tende a "atualizar" o código para a sintaxe do fork sem avisar, quebrando a versão que está em produção.

**Limites e boas práticas**
- A IA **mistura sintaxe entre as duas versões** do Materialize com frequência maior do que em frameworks mais populares — confirme sempre qual pacote (`materialize-css` legado ou `@materializecss/materialize`) o seu projeto usa antes de aceitar uma sugestão.
- Ela tende a "inventar" nomes de classe plausíveis (por analogia com Bootstrap) que não existem no Materialize — sempre teste no navegador antes de confiar.
- Peça para **explicar o "porquê"** de cada classe usada — entender o grid de 12 colunas e as variáveis Sass evita gambiarras de CSS customizado por cima do framework.
- Não cole design proprietário ou tokens de marca de clientes em ferramentas sem a política da sua empresa.
- Entenda o que você aceita: em entrevista e em produção, o HTML/CSS é seu — e quem mantém o projeto depois é você.

**Ferramentas de IA úteis no dia a dia com Materialize:**

- [Relume](https://www.relume.ai/) — Gera wireframes e componentes de site com IA, exportáveis com estilos prontos para adaptar.

## 💼 Carreira e vagas

Materialize aparece hoje em bem menos vagas de front-end no Brasil do que Bootstrap ou Tailwind — a maior parte da demanda que resta está em manutenção de sistemas legados (muitos ainda na v1, com jQuery), não em projetos novos. O que vale a pena levar de Materialize para uma entrevista é o domínio de CSS/Sass, grid responsivo e JavaScript puro para manipular componentes de UI, que transfere direto para qualquer outro framework. Dica: nos repositórios de vagas do GitHub abaixo, pesquise por "front-end" ou "CSS" nas issues abertas.
